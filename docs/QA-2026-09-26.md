# 留底 v0.1.2 回归验证

本轮对 v0.1.1 做追加测试，修复 3 类问题。测试使用虚构资料与独立浏览器会话，未操作个人资料。环境：Windows、Node.js 20.19.6、Chromium；GitHub CI 使用 Linux / Node.js 22。

## 发现与修复

### 1. 旧表单覆盖其他标签页刚保存的字段

复现：标签页 A 打开编辑；标签页 B 修改商家并保存；A 只修改诉求再保存。旧版提交全部表单字段，商家会回退到 A 打开时的值。

修复：与打开表单时的快照比较，只提交用户实际改动的字段。清空字段仍视为有效改动。不同字段的并行编辑可以合并；同时修改同一个字段仍以后保存的内容为准，不提供协同编辑冲突界面。

回归：两个数据库连接的自动测试及真实双标签页操作均保留了 B 的商家和 A 的诉求。测试包括字段清空与空白规范化。

### 2. 最终合并后的事项可能超过文字上限

复现：事项接近 1 MiB 文字上限时，旧快照的元数据更新与数据库中的最新时间线合并后可能超限；更新时间由短格式变为含毫秒格式，也会使边界记录超限。旧版检查发生在最终合并/更新时间之前，可能保存之后无法正常导出的记录。

修复：完整合并时间线和最终更新时间后，再校验将要写入的整个记录。验证失败时保留原资料。

回归：两项边界测试检查拒绝结果及数据库内容不变。

### 3. 接受了超出本应用导出契约的重新压缩 ZIP

复现：旧版接受外部工具重新压缩的备份；所用解压方式依赖 ZIP 声明的输出大小，无法可靠排除实际压缩流与声明大小不一致的情况。

修复：仅接受应用各版本一直导出的 STORE（不重新压缩）ZIP，提前拒绝压缩条目；继续验证两个头部的尺寸一致性、CRC、附件 SHA-256 与关联关系。提示用户选择原始备份。

回归：重新压缩的包被拒绝，数据库没有新增事项。既有 v1 原始备份和修复版导出均可恢复；同名附件仍独立保存。

## 验证结果

- `npm run check`：**54 项测试通过**，TypeScript 和正式构建通过。相比此前增加 5 项针对性回归。
- 从此前版本的真实导出 ZIP 恢复，新增一条日期不详的进展与两个同名附件；连同原附件共 3 个 `receipt.txt`，文件路径各异。
- 实际下载 ZIP 后，使用 Python `zipfile` / `hashlib` 独立核对 3 个附件 SHA-256、空日期、准备清单和 STORE 格式，均一致。
- 再次恢复为新副本，刷新后两份事项均在，记录、附件和勾选状态保留。
- 删除进展时“取消”保留原记录；确认删除后同时移除其两个附件，另一个事项副本仍保留完整资料。
- 标记办结后正确归档，原资料仍可查看。
- 390 × 844 视口无页面整体横向溢出；所测流程未报告未捕获浏览器错误。
- 正式版从缓存中的 v0.1.1 更新到 v0.1.2 后，原有事项仍保留；停止 HTTP 服务器并确认连接失败后，重新打开页面可加载已保存资料并导出材料包。

## 边界

上述结果覆盖列出的场景，不代表穷举所有输入或“零缺陷”保证。Safari、Firefox、手机真机、低内存设备及完整辅助技术体验仍未完成验收。数据仍只保存在当前浏览器；请定期导出原始 ZIP，保留外部副本。

旧版验证与已有离线检查见 [QA.md](QA.md)。
